evolora

self-improving fine-tuning, with python holding the leash

download for windows install on mac beta try it in the browser

100% free. trains on your own gpu. no keys, no cloud.

who checks the model?

python does. every single step.

the agent proposes, python disposes

Describe a specialty in plain English. A planner agent (a local Qwen model on your own machine, or MiniMax in the cloud) plans the evals, the training data and the LoRA hyperparameters. Python validates every step, trains the adapter, scores it against a locked benchmark and keeps the best one.

four guarantees
3
bounded agent tools, each validated in Python
SHA-256
locked eval set; any edit halts the run
9
explicit stop conditions, best adapter always kept
0 keys
needed for the mock path: no GPU, no network

01 / live run

Run the loop on the server

This starts the real Python orchestrator and streams every event it emits. Services marked fallback use labeled heuristics when no key is configured.

Run it on your computer

Not connected

Train for real on your own GPU, fully offline: no API keys, no cloud. Windows 10/11, or a Mac with Apple Silicon (beta).

  1. Windows: download and double-click EvoLoRA-Setup.cmd. Mac: run the Terminal command below. Either one installs EvoLoRA for your user only and starts it.
  2. Come back here and press Connect, then approve the request in the window that opens.
  3. Press Install everything once to fetch the local AI models and training tools.

Mac (Apple Silicon) beta

Open Terminal, paste this line and press Return. No password is needed.

curl -fsSL https://raw.githubusercontent.com/AkshayLanghani/EvoLoRA/main/public/download/install-mac.sh | bash

Needs an M1 or newer; Intel Macs are not supported. Training on the Mac GPU is new, so please report anything odd. If Safari cannot connect, use Chrome.

      02 / guardrails
      
          
      The agent proposes. Python disposes.
      
          
      Each card below sends your input to the same Python functions the loop uses.
      
        
      


        
      
          
      
            
      Hyperparameter snapping engine
      
            
      The agent picks LoRA settings with start_training_model. Anything off the allowed grid is moved to the nearest safe value before training.
      
            
      
              
              
              
              
              
              
            
      
            
      
          
      

          
      
            
      Locked eval set SHA-256 validator
      
            
      Eval prompts and answers are canonicalized and hashed. Edit an answer and verify: the loop re-checks this hash before every scoring step and halts on a mismatch.
      
            
            
            
      
              
              
              
            
      
            
      
          
      

          
      
            
      Deterministic objective scorer
      
            
      Responses for the demo task are scored on seven strict-JSON checks against the locked answer, which never leaves the host.
      
            
            
            
      
            
            
            
      
            
      
          
      

          
      
            
      Adapter naming preview
      
            
      Saved adapters lead with what they do. Generic lead-ins are stripped and a short run-id tag keeps each name traceable to its log.

      03 / how it works
      
          
      One iteration, split by who decides
      
        
      

        
        
      
          
      
            
              
      StepThe agent proposesPython decides
      
                  
            
              
      
                create_evals
                Criteria for a correct answer and concrete {prompt, expected_output} pairs for the goal.
                Locks and SHA-256 hashes the set, baselines the untrained model, and regenerates a harder set once if the baseline already scores 0.85 or more.
              
      
              
      
                add_training_examples
                Targeted {prompt, completion} pairs aimed at the observed failures.
                Drops malformed pairs and pairs whose prompt gives away the answer, normalizes completions to strict JSON and stacks examples across iterations.
              
      
              
      
                start_training_model
                Learning rate, rank, alpha, epochs and batch size.
                Snaps each value onto a fixed choice set, then trains: on your own GPU, with Unsloth on a GPU VM, or with the mock backend.
              
      
              
      
                Score and judge
                The retrain advisor says whether another round is worth it.
                Scores against the locked set. A judge model reviews the outputs (local Qwen3-4B, or Llama 3.3 70B on DigitalOcean). Expected answers never leave the host.
              
      
              
      
                Continue or stop
                -
                Stops on target score, max iterations, patience, judge acceptance, user decline, cancellation, eval tampering, repeated training failure or an unavailable backend, and keeps the best adapter.
              
      
                  
          
      
        
      
      
      
    
      


    
      
      
      
        
      
          
      04 / stack
      
          
      Models and moving parts
      
        
      

        
      
          
      
            
      
              Models
              
      RoleModel
      
              
                
      Specialized, on your computerQwen/Qwen2.5-1.5B-Instruct (default) or Qwen2.5-0.5B-Instruct
      
                
      Planner, judge and advisor, on your computerQwen3-4B (GGUF) served by llama.cpp
      
                
      Specialized, cloud GPUunsloth/Phi-3-mini-4k-instruct or unsloth/Meta-Llama-3.1-8B-Instruct
      
                
      Planner, data generator, retrain advisor, cloudMiniMax-M2.7-highspeed
      
                
      LLM-as-judge, cloudllama3.3-70b-instruct on DigitalOcean
      
                
      Voice STT / TTS (TUI, optional)deepgram/nova-3 / cartesia/sonic-3
      
                    
            
      
          
      
          
      
            
      
              Training backends
              
      BackendWhat runs
      
              
                
      mockThe whole loop with no GPU, keys or network.
      
                
      remoteParamiko SSH/SFTP to a GPU VM; streams live train and eval logs.
      
                
      localPyTorch with PEFT/TRL on your own GPU, with run history in SQLite. No keys, no cloud.
      
                
      unslothIn-process Unsloth boundary (optional extra).
      
                    
            
      
          
      
        
      
        
      Python 3.11+, Pydantic, FastAPI, Textual, Typer, llama.cpp, SQLite, Motor/PyMongo, Paramiko, and the OpenAI SDK for every OpenAI-compatible endpoint (local llama.cpp, MiniMax, DigitalOcean).

      Mock mode works with no setup
      
          
      One-click copy terminal blocks for local development and demos.
      
        
      

        
      
          
      uv sync
      
          
      uv run evolora demo --mock --iterations 2
      
          
      uv run evolora tui
      
          
      uv run uvicorn evolora.web.app:app --reload
      
        
      
        
      The last command serves this site and its API at http://127.0.0.1:8000. Use EVOLORA_PROFILE=local for the fully offline stack, or add keys from .env.example for cloud planner and judge services.
